# 公共服務網站無障礙整改｜需求及驗證

公共服務頁面的無障礙問題通常要交接給不同角色處理。驗證時應能還原初始問題、定位頁面元素、確認整改差異，並區分機器檢查與人工操作的結果。此工作台以兩個內建合成情境驗證這套流程。

| ID | 需求與可查交付 | 操作與預期證據 |
| --- | --- | --- |
| QA-01 | 依情境與啟用規則建立初測基線 | 案件進度及場地申請各為 4 項；停用對比則變為 3 項。停用全部時為「未啟用自動檢查」，禁止下載證據。 |
| QA-02 | 自動發現附規則、成功準則、節點、判定與修正建議 | 案件初測含 `#service-illustration` 無 alt、`#request-field` 無名稱、`#request-action` 無名稱、`#service-note` 有 2.25:1 對比。 |
| QA-03 | 修正真實 DOM，依規則與節點識別碼重算差異 | 依序整改為 4→3→2→1→0；核對新增 alt、label、按鈕名稱及文字計算色。基線維持 4、複測排除 4。重設或切換新情境重新建立基線。 |
| QA-04 | 分開記錄鍵盤及螢幕閱讀器的人工結果 | 自動歸零仍顯示兩項待覆核；人工填「需修正」不改變自動數。新一次掃描使先前人工結果回到待覆核。驗證只確認狀態機制及 Enter 可觸發合成動作，未完成整套輔具測試。 |
| QA-05 | 下載可追查的結構化證據，不夾帶輸入值 | [實際樣本](evidence-sample.json)列出情境、啟用規則、複測序號、基線與最新發現、差異、獨立人工狀態。下載後可核對初測 4、最新 0、排除 4、人工待覆核 2。 |
| QA-06 | 支援窄版檢視及基本鍵盤操作 | Chromium 實測 390px iframe（扣捲軸後內容 375px），無水平溢出；合成表單可從鍵盤 Enter 觸發本機狀態。 |

## 自動檢查範圍

- A11Y-01｜1.1.1：檢查圖片是否有 `alt` 屬性；內容是否貼切、空 alt 是否恰當仍需人工。
- A11Y-02｜3.3.2 / 4.1.2：檢查內建欄位的 label 或非空 ARIA 名稱來源；完整可見標籤、錯誤提示及輔助技術可讀性另驗。
- A11Y-03｜4.1.2：檢查內建原生按鈕的直接文字、ARIA 名稱來源；不替代完整的可及名稱計算。
- A11Y-04｜1.4.3：針對標記的一般文字，讀取不透明純色前景與背景，以 WCAG sRGB 相對亮度公式比較 4.50:1；不評估跨元素背景、圖片、漸層、透明度及變動狀態。

`npm test` 可重現對比公式、差異比對、節點讀取與證據結構。樣本及截圖取自實際瀏覽器操作；合成測試結果不具整站或標章效力。

## 用於實際站台時

先與負責角色確定抽樣路徑、適用版本、目標等級、第三方元件範圍與角色權限。接上授權的測試環境後，由維護者修正實際程式碼，再做跨頁與跨輔具回歸，記錄版本、時間、操作者、附件及覆核結果。爬站、系統串接、登入權限、留存管理及正式檢測應另定範圍；本機工作台不包含這些機制。
